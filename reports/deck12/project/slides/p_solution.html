WHAT TO SAY: Our solution has three parts. First, a downloader we wrote in Go. Every controller plugs into one policy interface, from a simple fixed setting to simple rules, a workload selector that guesses the kind of server, an online tuner modelled on a published method, a contextual bandit called LinUCB, and a neural-network agent called Double DQN. Second, a controlled test bench. Our own test server lets us set exactly how fast it answers, switch on a cap that punishes too many connections, and inject faults. We add network delay and packet loss with Linux netem, replay recorded mobile networks with Mahimahi, and finally check on real public mirrors. Third, fair measurement. We run every option back to back in random order, we write each experiment plan with its pass or fail rules before running it, we measure how much a perfect controller could gain before building any learning controller, and a script recomputes every number in our paper. We compare against aria2, axel, lftp and our own best fixed setting. HOW THEY DECIDE: the drop rule remembers the best recent speed it has seen; the first time the recent median falls below half of that, it switches once to a preset, for example 4 connections and 4 MiB pieces. The workload selector watches the first requests, decides whether the server is capped or healthy, and picks a preset. The online tuner nudges N up or down by a measured score. LinUCB and the Double DQN learn from a reward which action is best; the DQN reward is minus the seconds until the next request finishes, so a faster download scores higher. Each decision changes one dial, and N and S never change in the same decision. IN SIMPLE WORDS: A downloader that can turn the two dials mid-download, a lab where we control the conditions, and a fair way to score it. TERMS ON THIS SLIDE: • Policy: the decision-maker that looks at measurements and chooses what to do with N or S. • Drop rule: a simple rule that switches once to fewer connections when the speed halves. • Workload selector: watches the first seconds, guesses the kind of server, and picks a preset setting. • Online tuner: keeps nudging N up or down based on measured speed. • Learning controller: one that learns by trial and error, from a reward (reinforcement learning), which action to take. LinUCB is a contextual bandit, a simple reinforcement-learning method. Double DQN is deep reinforcement learning: a neural network that learns which action is best. • netem: a Linux tool that adds delay and packet loss. Mahimahi: a tool that replays recorded network speeds.
