WHAT TO SAY: Everything so far was on our own test setup. So we went to the real internet. From a home broadband connection in India we downloaded the Linux kernel source, about 64 MB, from four public servers: the kernel.org CDN, the kernel.org origin server, and university servers in Japan (RIKEN) and China (Tsinghua). We did this at four different times of day, with eight fixed settings plus aria2 and a single-connection tool, curl. The question: does the best setting change between servers and times of day? Mostly not. One setting, 8 connections × 1 MiB, was on average only 3.7 % slower than the best setting for each case. So even knowing the conditions in advance would gain very little. What did matter was using enough connections: on one server, 4 connections were up to 1.7 times slower. Side finding: the Tsinghua server in China refuses requests that carry Go’s default client name, so a plain Go downloader cannot use it at all. IN SIMPLE WORDS: On real servers, one sensible fixed setting was nearly always close to the best. THE CHART: each position along the bottom is one server at one time of day. Blue = our one fixed setting, grey = aria2. Height = how much slower than the best fixed setting for that case. The dashed line is 5 %. TERMS ON THIS SLIDE: • CDN: a content delivery network, servers spread around the world that deliver files from a nearby location. • Origin server: the main kernel.org server behind the CDN. • Client name (“User-Agent”): the name a program sends to identify itself to a server.
