WHAT TO SAY: After our formal reviews we gave the AI a fairer chance. The old simulator did not model the throttling server correctly, so we built a new simulator of it, tuned from real request logs, and checked it: its predictions were within 1.4 % of real runs. The retrained agent was 9 % faster than the fixed setting with the same 1 MiB pieces, on the server it was trained for. But on three new test conditions it had not practised on, it was faster in none. It had learned that one server, not a general skill. And it was still slower than big 32 MiB pieces and aria2. So we also tried an agent that can change piece size as well as connections. In the simulator, a simple hand-written rule showed there was a lot to gain, about 65 % less time. The trained agent did not find that behaviour: live it was slower than the best fixed setting in all four scenarios, up to 1.47 times. Because the simulator was accurate, the learning itself failed. IN SIMPLE WORDS: The AI could learn the exact server it practised on, but not generalise, and when we gave it more freedom it did not find the good strategy. THE CHART: dark bars = best fixed setting, blue bars = the agent that picks both dials; the label on each blue bar is how many times slower it was. TERMS ON THIS SLIDE: • New conditions (“held out”): test conditions deliberately kept out of training, to check the agent learned something general. • Simulator checked first: we predicted real results before running them, then compared.
