BCSE308P · When does adapting N and S help?

07

WHAT TO SAY: This is how segmented downloading works. The file is cut into ranges. Some are done, some are downloading right now, and the rest are waiting. Each range is fetched with one HTTP request, and the server answers “206 Partial Content”. More connections usually help, because many servers limit the speed of each connection: four connections get four times the speed. But they stop helping once your internet link is full, and some servers punish you for opening too many. The range size is a trade-off. Small pieces mean more requests but you can react quickly. Big pieces mean fewer requests, but one slow big piece can hold up the end of the download. WHY HTTP/1.1 (if asked): aria2, axel and lftp also use one HTTP/1.1 connection per segment. HTTP/2 and HTTP/3 carry many streams on one connection, which would change what N means, so we left them out. IN SIMPLE WORDS: N is how many lanes you open on the road; S is how big each truck is. TERMS ON THIS SLIDE: • 206 Partial Content: the server’s reply when it sends only the part of the file you asked for. • TCP connection: one network “pipe” between our computer and the server. • Bottleneck: the slowest link on the path, which limits the total speed. • Long tail: the end of a download where only one or two slow pieces are still running. • A request keeping its starting rate: on some servers, a request runs at whatever speed was in force when it started. Remember this; it explains two big results later.
