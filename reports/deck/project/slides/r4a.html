Test 4 · AI controllers that learn when to turn the dials

Inputs, actions and reward of the AI controllers

LinUCB · a simple learner

Sees 10 numbers: N, S, speed per request, total speed, request time, bytes done, counts of successes, failures, retries

Can do 5 actions: nothing, N up or down, S up or down

Reward more total speed, fewer retries and failures, a small cost for changing anything

Double DQN · a neural network

Sees 13 numbers: N, bytes left, total speed (now, smoothed, trend, jumpiness), request time and its trend, recent failures and retries, time since the last change

Can do 3 actions: nothing, add or remove a connection (the joint agent also changes S)

Reward minus the seconds until the next request finishes, so a faster download scores higher

Total speed is an input because speed per request does not change with N, so an agent could not learn from it. One decision after each finished request; a running request is never cancelled.

N: connections · S: piece size · DQN agents train in a simulator of the server and run inside our downloader

WHAT TO SAY: Before the AI results, here is exactly what these controllers are given. Both work the same way: after every finished request, the controller looks at some numbers, picks one action, and later gets a score. LinUCB sees 10 numbers: how many connections (N) and how big the pieces (S) are right now, the speed of one request, the total speed of all requests together, how long the last request took, how many bytes are done, and how many requests succeeded, failed or were retried. It can do five things: nothing, more or fewer connections, bigger or smaller pieces. Its score is higher for more total speed, lower for retries and failures, and there is a small charge for changing something. The neural network, called Double DQN, sees 13 numbers. They include the current N, how much of the file is left, the total speed now, a smoothed version of it, its trend and how jumpy it is, the request time and its trend, recent failures and retries, and the time since it last changed anything. Our main agents can only add or remove one connection, or do nothing; the piece size stays at 1 MiB. The joint agent can also change the piece size. Its score is simply minus the seconds until the next request finishes, so over a whole download the score is about minus the download time. We did not tune any reward weights. We use the total speed because speed per request does not change when you add a connection, so an agent cannot learn what its action did from that number. We checked this before testing any agent. IN SIMPLE WORDS: The controller is told how the download is going, chooses one small change, and is rewarded when the download gets faster. TERMS ON THIS SLIDE: • N: how many connections run at once. S: the size of each piece. • LinUCB: a learner that keeps a running estimate of how good each action is and tries ones it is unsure about. • Double DQN (deep Q-network): a neural network that learns to predict how good each action is; “double” is a trick that makes the prediction less over-optimistic. • Reward: the score the learner gets after an action; learners try to make it large. • Smoothed, trend, jumpiness: a running average of the speed, how fast it is rising or falling, and how much it bounces. • Simulator: a fast program that imitates the server, so the agent can practise thousands of downloads before the real one.
