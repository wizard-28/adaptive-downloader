WHAT TO SAY: Now the machine-learning part. We tried two kinds of learning controllers. First a simple learner called LinUCB; it quickly got stuck always choosing the same action. Then neural-network agents of a kind called Double DQN, through several versions: one that turned both dials, one allowed up to 4 connections, one allowed up to 16. All of them took longer than aria2, between 1.5 and 2.3 times as long. Part of that was unfair to them: the test files were small, so the agent had little time to act, and one version started with a single connection while aria2 opens 16 at once. So we gave the 16-connection agent a long file and a start at 16 connections on the throttling server; it still took 1.36 times the best fixed time. A different approach, which first tries to work out the server’s rules and then picks a setting, failed its own test in simulation, so we never ran it for real. How the neural agent works: after each piece finishes, it looks at 13 measurements of the download, then chooses to do nothing, add a connection, or remove one. It is rewarded for finishing sooner. It learns in a simulator, and the trained network then runs inside our downloader. IN SIMPLE WORDS: Our first AI controllers learned, but what they learned did not beat a sensible fixed choice. TERMS ON THIS SLIDE: • Reinforcement learning: learning by trial and error; the agent tries actions and gets a reward. • LinUCB: a simple learner that picks one action at a time and learns which pays best; it does not plan ahead. • Double DQN (Deep Q-Network): a neural network that estimates how good each action is in the long run; “double” is a fix that avoids over-optimistic estimates. • Simulator: a fast imitation of the download used for training.
