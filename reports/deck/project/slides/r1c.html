WHAT TO SAY: Is the gap to aria2 just an aria2 quirk? We ran two more popular download tools, axel and lftp, on the same four server conditions, all with 16 connections. The chart shows how long each took, in seconds. Shorter is better. When the server has no cap, or is slow first and then fast, aria2, axel and lftp all take about 53 seconds. Our fixed setting takes 18 to 20 seconds, about a third of the time. These tools all cut the file into 16 equal parts right at the start, so their big pieces keep the slow speed they started with. Our smaller pieces start later and get the fast speed. When the server caps the speed from 8 seconds, everything is level at about 53 seconds. No winner. When the cap is on from the very start, ours, aria2 and axel take about 66 to 68 seconds; axel is 2.5 % faster than ours. lftp takes 114 seconds, because it never re-splits a slow piece and so waits for the slowest connection at the end. Our own engine without splitting behaved the same way earlier, which is why we added splitting. We left out wget2, because it can only fetch one file over a single connection, and IDM, because it is closed and Windows-only. IN SIMPLE WORDS: Any tool that cuts the file once at the start suffers on a server that speeds up later. It is not special to aria2. TERMS ON THIS SLIDE: • Cap: a limit the server puts on the total speed when too many connections are open. • Fixed setting: the same number of connections and the same piece size for the whole download. • Re-splitting (straggler splitting): when one connection is idle at the end, it takes over half of the slowest piece. • Round: one run of every tool, in random order. • Quick check (“screen”): a small experiment to see a direction, not final proof.
