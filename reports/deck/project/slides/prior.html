Before our work · what others did

Earlier work shows tuning can help. Four questions stay open.

What earlier work did

Tune the number of connections while transferring: direct search, a utility function, gradient descent (Balaprakash, Falcon, FastBioDL)

Share a download across servers and size the pieces for each server (MDTP)

Adapt task size with deep learning for short-video preloading (DeLoad)

What we did not find in the papers we read

  1. A race against aria2, axel and lftp and the best fixed setting of the same engine
  2. How much a perfect controller could gain, measured before building one
  3. Controller gains separated from engine effects: timeouts, splitting, when requests start
  4. Cases where adapting gave nothing, or lost

Based on abstracts, and the full text for FastBioDL · a statement about what we read, not about all prior work

WHAT TO SAY: Before our own work, what had others done? Several groups tune how many connections a transfer uses while it runs. Balaprakash and colleagues used a search method on production scientific links. Falcon uses a score that balances speed and cost. FastBioDL, aimed at genome downloads, nudges the number of connections up or down using gradients. MDTP shares one download across several servers and sizes the pieces for each server. DeLoad uses deep learning to size download tasks for short-video preloading. These works show that tuning can help. But in the papers we read, we did not find four things. First, a race against several stock tools such as aria2, axel and lftp together with the best fixed setting of the same program. Some compare with fixed settings or with other tools, but not both on one engine. Second, a measurement of how much a perfect controller could gain, made before building the controller. Third, a separation of the controller’s gain from engine effects, such as request timeouts, splitting slow pieces, or when requests start. Fourth, cases where adapting gave nothing or lost. We are careful: we read abstracts, and the full text only for FastBioDL, so this says what we found in what we read, not that nobody has ever done it. IN SIMPLE WORDS: Others asked how to tune the number of connections. We ask whether there is anything to tune, and where the gain really comes from. TERMS ON THIS SLIDE: • Concurrency (N): how many connections run at once. • Fixed setting: the same N and piece size for the whole download. • Perfect controller (“oracle”): an imaginary controller that knows the future; it shows the most any real controller could gain. • Engine effects: behaviour of the downloading machinery itself, such as timeouts and splitting, as opposed to the controller that picks N and S. • Direct search, gradient descent, utility function: three ways of improving a setting by trying changes and keeping the better ones.
