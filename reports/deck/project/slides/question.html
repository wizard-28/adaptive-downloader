The question

If conditions change during a download, should the downloader change with them?

Dial 1: N

how many pieces we download at the same time (connections)

Dial 2: S

how big each piece is, for example 1 MiB or 32 MiB

What we test

Does turning the dials mid-download beat aria2 and similar tools, which set them once? And beat our own best fixed setting?

“Changing conditions”: server speeds up or slows down, server throttles, network delay and packet loss, unstable mobile links

02

WHAT TO SAY: Every parallel downloader has two dials. N is how many pieces it downloads at the same time. S is how big each piece is. Tools like aria2 set both dials once, at the start, and never touch them again. Our idea: if conditions change during the download, a downloader that turns the dials as it goes should do better. We tested that against aria2 and similar tools. We also compared against our own downloader with the best fixed setting, so we can tell whether a win comes from adapting, or just from choosing the dials better at the start. NOTE: delay and loss were tested as fixed settings in each run; we did not change them while a download was running. IN SIMPLE WORDS: Imagine the server suddenly slows you down halfway through. Should you open more connections, fewer, or change piece sizes? And does doing that beat a tool that never changes anything? TERMS ON THIS SLIDE: • Connection: one network link between our computer and the server, carrying one piece at a time. • MiB: mebibyte, about one million bytes (1,048,576). • Fixed setting: one choice of N and S kept for the whole download. • Throttling: a server deliberately limiting how fast it sends.
