WHAT TO SAY: So, on those wildly swinging networks, does adapting help? Instead of building an AI first, we asked: what is the most any controller could gain? We computed a perfect controller that knows the future and picks the best number of connections for each 120-second stretch, paying the real cost of each switch. Even it was only 0.41 % faster on average than simply keeping the best fixed number. We had decided in advance that adaptation would only be worth pursuing if this ceiling was at least 10 %. Even the cautious lower estimate was below zero, so the answer is no. The reason: when the network gets slower, every setting gets slower together. The best number of connections stays about the same, roughly “enough to fill the pipe”. IN SIMPLE WORDS: The network changing a lot does not mean there is anything to gain by changing settings. Variability is not opportunity. TERMS ON THIS SLIDE: • Perfect controller (“oracle”): imaginary, knows the future. It gives a ceiling: no real controller can beat it. • Ceiling (“headroom”): how much faster the perfect controller is than the best fixed setting. • Cautious lower estimate (“one-sided 95 % lower bound”): the value we can be fairly sure the gain is at least. It was −0.26 %, so we cannot even be sure the gain is above zero. • Recording (“trace”): see the previous slide; these are capacity-only replays.
